# Hallucination Scanner

## Intent

Two questions every AI Champion cohort eventually asks:

> *"How are we scanning for hallucinations / purely incorrect information?"*
>
> *"We need to verify every output for accuracy — how do we do that at scale?"*

And a real-world pattern that keeps recurring: a subject-matter-expert bot confidently
recommends something wrong, and the wrongness is only caught because someone happened
to double-check. This skill gives every Champion a repeatable second pass that catches
hallucinations before they reach a customer, partner, or leader.

## When to use

- Any content generated by a Custom GPT, Claude Project, or other AI before it's
  sent outside your team
- Competitive intel, analyst talking points, case studies, GTM frameworks
- RFP / RFI responses, technical partner guides, product comparisons
- Blog drafts, email copy, and landing page copy that cite numbers or features

Especially important when the generating tool had large context (dozens of SOPs, product
docs, etc.) — large context is where hallucinations hide best.

## Instructions

### 1. Require inputs

This skill needs two inputs:

- **Content under review** — the AI-generated text
- **Source set** — the documents, URLs, or passages the content is supposed to be based on

If no source set was provided, return:

```
BLOCKED: No source set provided. I cannot verify claims without authoritative sources.
Either attach the source documents/URLs, or mark the content as "opinion" rather than factual.
```

### 2. Extract atomic claims

Break the content into individual factual claims. A claim is any assertion that is either true or false.

Do this aggressively — a single sentence can contain 2–4 claims.

> "Our platform supports 50+ integrations including Salesforce and HubSpot, and deploys in under 10 minutes."

→ 3 claims:
- Platform supports 50+ integrations
- Salesforce is an integration
- Deploys in under 10 minutes

### 3. Verify each claim against the source set

For each claim, determine one of:

- **SUPPORTED** — source directly states or implies this claim
- **UNSUPPORTED** — no source mentions it (≠ false, but cannot be verified from given sources)
- **CONTRADICTED** — a source states the opposite

For SUPPORTED claims, cite the source (filename, URL, section, or quote).

### 4. Return a structured report

```
HALLUCINATION SCAN REPORT
=========================

Summary:
  Total claims:       N
  Supported:          X (% )
  Unsupported:        Y
  Contradicted:       Z

Risk: <LOW | MEDIUM | HIGH>
  LOW    = all claims supported; safe to send with a final human read
  MEDIUM = 1–3 unsupported claims; add citations or soften language
  HIGH   = any contradicted claim, or >3 unsupported claims; rewrite required

Findings:

1. CONTRADICTED
   Claim: "Deploys in under 10 minutes"
   Source says: "typical deployment takes 2–4 hours" (product-docs.md §Install)
   Recommended action: Correct to match source, or remove the claim.

2. UNSUPPORTED
   Claim: "50+ integrations"
   No source in the set lists a count.
   Recommended action: Either cite a source with the count, or rewrite as "many integrations".

3. SUPPORTED
   Claim: "Salesforce is an integration"
   Source: integrations-list.md line 14: "Salesforce (native connector)"
   No action needed.
```

### 5. Output

Only the report. Don't offer to rewrite the content — let the human decide what to do
with each finding.

## Anti-patterns

- Don't assume a claim is true because it's "common knowledge" — the whole point is to
  check against the given sources, not your prior beliefs
- Don't treat nearby wording as support — "50+ integrations" is NOT supported by a source
  that says "many integrations"
- Don't merge claims. Split aggressively, verify individually.
- Don't be lenient on numbers, dates, or comparative claims. Those are where customers
  and partners will spot you.
